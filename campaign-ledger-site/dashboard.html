Optional Claude integration
The downloadable Python tool includes a Claude API adapter that selects source-linked facts and suggests investigation questions. Numeric facts are checked against SQL results; invalid responses fall back to the rules-based review. It requires a server-side API key and model setting. This public demo does not call Claude, and no live Claude response has been verified.

Metric definitions

CAC, ROAS & attribution
CAC divides ad spend plus sample allocated acquisition costs by new customers in the selected window. Net ROAS divides gross attributed order revenue minus refunds recorded in that window by ad spend. Refunds follow refund dates; this is not an order-cohort return rate. Each fictional order has one campaign attribution. Product costs, shipping, taxes, and overhead are not modeled, so this report does not calculate profit.

When an import fails

The pipeline retries temporary HTTP errors up to three times. If a source remains unavailable or validation fails, it logs the failed attempt and keeps the last valid snapshot. Operations investigates the source and reruns the workflow. The report must remain labeled as a retained snapshot until a successful refresh.

When a source corrects a record

This adapter expects complete snapshots for the same reporting window. A corrected snapshot safely replaces the earlier one. Stable record IDs prevent duplication, and rerunning the same snapshot leaves metrics unchanged. Partial incremental feeds would need a different adapter.

Who uses the result?

Operations owns import failures and reconciliation. Growth reviews spending and performance flags. Data or Product investigates tracking discrepancies. A team member approves any targeting or budget change; this tool does not write to advertising accounts.

What is implemented?

Python HTTP adapters with retries, source checks, transactional SQLite imports, persistent run history, refund-aware reporting, segmentation, exports, threshold alerts, and a rules-based brief. The optional Claude adapter is tested with simulated API responses. Public controls replay generated outcomes; they do not start a hosted Python service.

What would production require?

Authorized Meta, Google, and store connectors; reconciled attribution and currencies; a persistent hosted database; a scheduler or low-code workflow platform; monitoring; and a verified Claude connection. These are not deployed in this demo.
