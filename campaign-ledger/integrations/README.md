# Workflow operations

This prototype is an independent example using entirely fictional data. No actual ad accounts are connected. The Meta and Google labels are mock sources, not implementations of their official API contracts.

## Run the complete HTTP workflow

In one terminal, from `campaign-ledger`:

```
python3 mock_sources.py --scenario success --port 8765
```

In another:

```
python3 workflow.py --base-url http://127.0.0.1:8765
```

The pipeline requests `/meta`, `/google`, and `/store`, validates their envelopes and records, replaces a complete snapshot in SQLite, and writes `output/workflow.json`. The database includes persistent success/failure history. Validation uses a fixed fictional reference clock of October 3, 2026 at 09:00 UTC; this is deliberately not a live freshness monitor.

Restart the mock server with `--scenario failure`, then rerun the workflow. Google returns HTTP 503. The adapter retries three times, records failure, and preserves the earlier report. Restart with `--scenario correction` and rerun: a $50 spending correction and an additional sample refund replace the previous records. Rerunning does not multiply money or orders.

## Trigger and orchestration contract

The CLI is a manual trigger. It exits 0 for success and 1 for failure, allowing a future scheduler or low-code workflow to branch on the outcome. An orchestration sequence would be: scheduled trigger -> authorized source adapters -> workflow -> status check -> report publication or issue alert -> human review. No scheduler or low-code platform is installed or deployed. Real APIs require authentication, pagination, separate source contracts, and explicit completeness checks; do not point this adapter directly at Meta or Google endpoints.

## Optional Claude tool

Configure `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` as server-side environment variables, then use `--claude`. Never put a key into the HTML or commit it. The adapter calls Anthropic's Messages API with aggregate campaign metrics. It accepts only known campaign/metric references with exactly matching numeric values. It returns investigation questions for human review. Missing configuration, API failures, or invalid output retain the rules-based review path. Tests use simulated responses; no paid live Claude call was made or verified. This is a narrow review tool, not an autonomous budget-optimization agent.

## Definitions and limits

Gross attributed revenue sums orders by order date. Revenue after refunds subtracts refunds by refund date in the selected window. Net ROAS divides that value by advertising spend. It is not profit and is not the same as platform-reported ROAS. Each sample order has one campaign; cross-platform attribution overlap is not modeled. Real attribution reconciliation must be agreed with Data and Growth before comparing live platform figures.

## Team procedure

Operations investigates missing or stale sources and reruns failed imports. Growth checks flagged changes against campaign context. Data/Product owns tracking inconsistencies. A human reviews any model-generated questions and authorizes campaign changes separately. Successful imports do not establish that every upstream record is accurate.

## Public demo and reproducibility

The public Site replays three JSON outcomes generated by actually running the Python HTTP-to-SQL pipeline. It does not start Python, call advertising platforms, or invoke Claude in a visitor's browser. Regenerate after code or data changes:

```
python3 -m unittest -v test_report.py test_workflow.py
```

From the sibling `campaign-ledger-site` folder:

```
python3 build_scenarios.py
python3 build_site.py
node check_dashboard.cjs
```
